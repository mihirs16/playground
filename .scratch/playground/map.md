# playground — wayfinder map

## Destination

A written spec for each of the five components — **custodian**, **broom**, **blank**, **persona**, and **deed** — plus the cross-cutting architecture decisions those specs depend on, recorded as ADRs under `docs/adr/`.

Reaching the destination means nothing is left to decide before someone starts building. It does **not** mean anything is built.

## Notes

- **Domain**: a polyglot monorepo "digital playground" replacing the deprecated Next.js + Notion site at [`mihirs16/mihirsingh.dev-deprecated`](https://github.com/mihirs16/mihirsingh.dev-deprecated). The playground exists to learn, experiment and practise smaller software concepts.
- **Plan, don't do.** Every ticket resolves a decision. No implementation in this map — the four spec documents are the deliverable. The pull to start building is the signal we've reached the edge of the map.
- **Skills each session**: `/grilling` and `/domain-modeling` by default. `/research` for `research` tickets (AFK). `/prototype` for `prototype` tickets (HITL).
- **Subagent sizing** _(standing preference)_: run subagents on the smallest capable model at lower effort — default `research`/`task` agents to Sonnet (drop to Haiku for mechanical work); reserve the top model + higher effort for the driving session's own reasoning. For agents run via a workflow, also lower the per-agent `effort`.
- **Polyglot is incidental, not a goal.** Best tool per component. Do not force language variety for its own sake.
- **The design language is recoverable, not invented.** Harvested from the deprecated repo's CSS modules: Roboto Mono throughout (Poppins imported but barely used); monotone `#000000` / `#5F5F5F` / `#FFFFFF` plus greys `#5C5C5C` `#969696` `#9C9A9A` `#9E9C9C`; the yellow is **`#FBFF20`**, used exactly twice; signature detail is `h3:after` — a 1px rule that flexes to fill the line after each heading.
- **Cautionary fact**: the deprecated site put its Notion token in `NEXT_PUBLIC_NOTION_KEY`, which inlines it into the client bundle. custodian's auth model must not repeat this.
- **Core motivation**: the deprecated site used `getStaticProps` with no revalidation, so every content edit required a rebuild. Escaping that is the point of custodian.
- **Infrastructure principle** _(from ticket 01)_: **self-manage the compute, rent the durability.** Self-manage what fails as "it's down an hour and you learn something"; rent what fails as "the data is gone." Everything lives in **AWS eu-west-1** at ~£10/month. See [ADR-0001](../../docs/adr/0001-hosting-and-deployment-posture.md).

## Decisions so far

- **Destination is specs, not shipped code** _(charting)_ — all four components specced before building; cross-cutting decisions become ADRs.
- **Polyglot is incidental** _(charting)_ — best tool per component, no forced variety. `blank` is TypeScript by necessity, since it's a Web Components library.
- **custodian owns all three content buckets** _(charting)_ — **authored** (markdown blogs + media), **derived** (Steam currently-playing, GitHub activity — fetched and cached, never written by hand), and **profile** (about, experience, skills, resume link). Profile moving into custodian is deliberate: leaving it as repo files would partly recreate the rebuild-to-edit problem.
- **Curated projects and GitHub activity are two separate concepts** _(charting)_ — a showcase you author and order deliberately, plus a live feed custodian observes. Different lifecycles, different trust levels, rendered differently.
- **`blank` publishes to public npm with semver from the start** _(charting)_ — not because strangers will use it, but because publishing is the forcing function that stops the API silently becoming persona-shaped.
- **persona bakes profile at build time; blogs, Steam and GitHub load at runtime from custodian** _(charting)_ — custodian is therefore a hard runtime dependency for blog content, which is why health monitoring and alerting are an explicit requirement rather than a nice-to-have.
- **[CLI: name](issues/06-cli-name.md)** — the CLI is **`broom`**, the custodian's own implement. Pairs with `custodian` as a set, and stays humble about a tool that only moves content into an API. Bare npm name is squatted by a dead 2012 package, so npm distribution would need a scope; Homebrew and Go paths are clear, crates.io unverified.
- **[Hosting and deployment posture](issues/01-hosting-and-deployment-posture.md)** — all AWS, eu-west-1, ~£10/mo. custodian is a long-lived **EC2 `t4g.micro`** running nginx + systemd by hand, with **SQLite in-process** replicated to **S3**; media is S3; persona is a private S3 bucket behind **CloudFront**, leaving Netlify. **One CloudFront distribution fronts both**, so blogs cache at the edge and the API is same-origin. Credentials come from an **IAM instance profile** — nothing long-lived on disk, which is what won AWS over a cheaper Hetzner + R2 build. DNS delegates to Route 53.
- **The destination is redrawn to five components** _(surfaced by [Hosting and deployment posture](issues/01-hosting-and-deployment-posture.md))_ — **`deed`**, the Terraform component, joins the set. The name follows the rule: a single evocative noun, the authoritative declared record of the ground the playground sits on. It provisions the playground *and* projects beyond it, which gives it `blank`'s property — its interface must not become playground-shaped.
- **[Authored-content domain model](issues/03-authored-content-domain-model.md)** — the ubiquitous language for all three buckets, now in `CONTEXT.md`. `log` is the one first-class authored type (fields + `listed`/`unlisted` state where every log is link-reachable and slug freezes only while listed; **GFM core**, no footnotes, no novel syntax, blockquote doubles as margin aside). `media` is independent and generic-URL'd with a `broom` reference-check before delete. `profile` is a keyed id+`body` table (`about`/`experience`/`skills`/`resume-link`/`curated-projects`, opaque JSON, no custodian validation); `integration` mirrors that shape for derived sources. **Scope held:** the Notion-style user-defined-type/BaaS idea was ruled a future direction, not v1 — same "capable-of, don't-build" framing as `blank`/`deed`.
- **[blank: design language extraction](issues/04-blank-design-language-extraction.md)** — the design language, verified against the deprecated `globals.css` and resolved by prototype. **Roboto Mono 400 for all chrome; hierarchy from spacing plus a small size step, never weight** — whitespace does the majority over a gentle 20/16/15px scale (h1/h3/body) well below the old CSS's 32/20/14. **Colour balanced against size** so presence is uniform: the larger the element the more its ink fades (h1 `#5F5F5F`, body full ink). **Headings centered and standing alone, body text justified and block-centered on the page**; the recovered `h3:after` hairline rule is dropped (no flanking rules on centered headings). **Everything is lowercased (leading letter included) — chrome *and* headings — except running body prose**, which keeps authored casing; casing marks the one class of text meant to be read normally. **Roboto Serif for long-form prose** — the chosen companion, kept inside the Roboto superfamily so it shares the skeleton. Poppins confirmed dead, dropped. **Fearlessly monotone**: `#FBFF20` kept exact and used **only as a background highlight** — links are ink-underline, status dots ink, and in data viz the yellow is a single spark, never a fill. `h3:after` kept verbatim as the heading rule. **Dark theme is first-class from the start** (the monotone palette makes it cheap, and it reads better than light). Validated viz primitives — **square stat tiles** and a **drawn SVG line/area chart with mono axis labels** — belong in the component inventory.
- **[blank: Web Components strategy](issues/05-blank-web-component-strategy.md)** _(research)_ — primary-source facts for the Lit-vs-vanilla and Shadow-vs-light-DOM calls; full findings in [`research/05-blank-web-components-strategy.md`](research/05-blank-web-components-strategy.md). Lit is a **~5 KB** versioned runtime giving property/attribute sync + batched render + template diffing you'd otherwise hand-write; Shadow DOM is the first-party default (Lit calls light DOM "generally not recommended"); **`adoptedStyleSheets`** (Baseline Mar 2023) kills per-instance style duplication; theming crosses the boundary only via inherited **custom properties** + opt-in `::part()`/`::slotted()`. **Pivotal SSR asymmetry:** **Declarative Shadow DOM is a platform feature, Baseline Aug 2024, works everywhere; Lit's own SSR is experimental (`@lit-labs/ssr`)** — so vanilla pre-renders library-independently while Lit's pre-rendering leans on non-stable tooling. React 19 closed the last framework-interop gap (100% Custom Elements Everywhere); Astro/Svelte/Vue already fine. **The Lit-vs-vanilla decision itself is deferred to [blank: rendering foundation](issues/21-blank-rendering-foundation.md), which now gates [persona: framework](issues/15-persona-framework.md) in place of this research.**
- **[Steam and GitHub API capabilities](issues/02-steam-and-github-api-capabilities.md)** — both APIs support a poll-and-cache model well inside their rate limits (Steam: 100,000 calls/day; GitHub: 5,000/hr authenticated, 304s free); the real constraint is freshness *shape*, not quota. Steam: a self-owned key bypasses privacy gating entirely, and `GetRecentlyPlayedGames` beats live presence for a rarely-polled site. GitHub: `events/public` polled every 1–2 min with a zero-permission PAT and ETag conditional requests, but GitHub documents 30s–6h latency on that feed — UI copy must say "recently active," not "live."
- **[custodian: storage model](issues/08-custodian-storage-model.md)** — **SQLite is the sole source of truth** (the git-hybrid fork weighed and dropped — it adds git *on top of* `07`'s embedded engine and forks `01`'s one-file durability path). `log` bodies are a column; **version history deferred** (overwrite-in-place + `created_at`/`updated_at`; a `log_revision` table is additive fog). **Media keys are a single kebab-case string** — author-given or random-kebab, uniqueness *enforced* (duplicate → error, no silent overwrite), URL extension-free (`cdn.mihirsingh.dev/<key>`) with content-type from the record; content-addressing rejected (dedup irrelevant, immutability fights image-swap). **`integration` cache shares the same SQLite store** (no Redis/in-memory — one boring durable thing). **Recovery: Litestream-style WAL shipping for per-timestamp PITR + S3 versioning on both DB and media buckets, 30-day retention** — covers self-inflicted bad writes/deletes, not just instance loss. *Open caveat: confirm the 30-day retention S3 cost against `01`'s ~£10/mo when buckets are configured.* Unblocks `09`; writes are fully synchronous.
- **[custodian: API contract](issues/09-custodian-api-contract.md)** — **REST/JSON, OpenAPI 3.1 spec-first** (Go + TS clients generated from one `.yaml`). **Two surfaces in one binary, split by audience:** a public `/v1/*` read surface (unauth, GET-only, `ETag`+`Cache-Control`+`304`, static-config CORS allowlist) and an authenticated admin `/admin/v1/*` CRUD surface (`no-store`, no CORS). **Media** uploads via **presigned S3 `PUT`** — reserve (`pending`, key uniqueness enforced) → upload → `confirm` (custodian `HEAD`s S3) → `available`; stale reservations reaped by the existing poller; `broom` needs no AWS creds. **Slug is a log's sole identity** (mutable while unlisted, frozen while listed; rename is a server move); logs are `POST`/`PATCH`/`DELETE` with `state`/`slug` as fields. Profile `PUT`-upsert opaque; integrations poller-driven + a manual `/refresh`. Errors are **RFC 9457 `problem+json`** + stable `code`. Versioned by **URL path `/v1`** (additive-only within a major). *No spec artifact built — the decision record carries draft request/response sketches; the OpenAPI `.yaml` is destination-spec work.* Unblocks `10`/`12`/`17`; hands `12` the TTL numbers and `10` the header-not-cookie auth scheme.
- **[custodian: language and runtime](issues/07-custodian-language-and-runtime.md)** — **Go**, as a single static binary. Boring/debuggable for the must-stay-up component *and* career-aligned learning, so maintenance and novelty point the same way (Rust dropped as maintenance burden, TS dropped since its markdown/type-sharing edge is weak — goldmark exists, types go via `09`'s OpenAPI client). **Pure-Go `modernc.org/sqlite`** keeps `CGO_ENABLED=0` cross-compiles to ARM64 with no C toolchain — single-binary story intact, S3 replication stays file-level/driver-agnostic. **chi** for HTTP (it *is* `net/http`, so no lock-in and it scales via sub-routers if custodian fronts other projects). AWS SDK **Go v2** covers the IMDS chain natively; comfortably inside the 1 GB/ARM64 envelope, no day-one resize.

## Not yet specified

In scope, but not yet sharp enough to ticket. Graduates as the frontier advances.

- **The five spec documents themselves** — the destination artifacts. Written once enough decisions have landed; can't be phrased as a question until then.
- **Migrating existing Notion content into custodian** — a one-off import of about / experience / projects / skills / resume-link. Shape depends entirely on custodian's storage model.
- **Media pipeline beyond raw upload** — image optimisation, responsive variants, formats, whether custodian transforms on ingest or on read. Ticket `01` settled *where* media lives (S3) and `08` settled the key scheme (derivatives slot under `<key>`); what remains — formats, variants, transform-on-ingest-vs-read, and whether originals are kept alongside derivatives — now waits on `blank`/persona rendering needs, not `08`.
- **Testing strategy per component** — differs sharply between a Go/TS API, a CLI, a Web Components library, and a static site. Waits on language choices.
- **CI/CD shape** — what builds, what publishes, and in what order across a polyglot monorepo. Waits on monorepo tooling. The *deploy* slice has graduated to `19` (what `deed` provisions versus what a deploy does); what remains here is build and publish.
- **`blank`: accessibility** — the monotone palette makes contrast unusually tractable, but the component inventory has to exist first. _(Dark mode is no longer open — `04` settled it as a first-class token layer from the start; what remains here is contrast/focus/keyboard accessibility of the actual components.)_
- **persona: full page and route inventory** beyond blogs and the live-status surface.
- **Release and versioning process** for the monorepo as a whole, given `blank` publishes publicly and the others don't.
- **Analytics**, if any.
- **`snippet` — the short-form writing type** _(from `03`)_. Deliberately deferred past v1; likely arrives as a summary *derived from* a log rather than a separately authored type. Can't be ticketed until logs exist and the "summary vs. standalone" question is live.
- **LaTeX / math in log bodies** _(from `03`)_. Wanted, explicitly not v1. Adds a parser extension beyond GFM core and a `blank` rendering concern; revisit after the component inventory and a storage/render decision.
- **Log `description`/excerpt field** _(from `03`)_. Held back until the blog-list UI design shows whether a list needs its own summary text distinct from `subtitle`. Waits on `blank`/persona surfaces.
- **`custodian` as a generic user-defined-type layer (BaaS / playground-as-platform)** _(from `03`)_. Ruled a future *direction*, not this destination — captured with the same "capable-of, don't-build" framing as `blank`/`deed`. Would only graduate under a redrawn destination, and even then storage/API should merely not *preclude* it. Borderline out-of-scope; kept in fog because the v1 storage and API shapes (`08`/`09`) should avoid foreclosing it.
- **The cutover** from the deprecated Netlify deployment. Ticket `01` settled where DNS lands — registration stays at Squarespace, nameservers delegate to Route 53 — but not the sequencing: TTL lowering, cert validation before the switch, and how to avoid a window where neither site serves.

## Out of scope

Ruled beyond this destination. Never graduates — returns only as a fresh effort if the destination is redrawn.

- **Building any of it.** The destination is specs. Implementation is a separate effort per component.
- **Incrementally migrating the deprecated site.** persona is a port to a new environment, not a refactor in place. The old repo is a source of design tokens and a content model, nothing more.
- **Adopting `blank` in other personal projects.** `blank` must be *publishable* and its API must not be persona-shaped, but actually wiring it into other projects is their own work.
- **The deprecated site's Notion workspace** beyond reading what content types it held. No two-way sync, no keeping Notion in the loop.
- **Actually provisioning non-playground projects with `deed`.** `deed` must be *capable* of it — its interface must not become playground-shaped — but standing up other projects' infrastructure is their own work. Mirrors the `blank` ruling above.
