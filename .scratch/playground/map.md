# playground — wayfinder map

## Destination

A written spec for each of the five components — **custodian**, **broom**, **blank**, **persona**, and **deed** — plus the cross-cutting architecture decisions those specs depend on, recorded as ADRs under `docs/adr/`.

Reaching the destination means nothing is left to decide before someone starts building. It does **not** mean anything is built.

## Notes

- **Domain**: a polyglot monorepo "digital playground" replacing the deprecated Next.js + Notion site at [`mihirs16/mihirsingh.dev-deprecated`](https://github.com/mihirs16/mihirsingh.dev-deprecated). The playground exists to learn, experiment and practise smaller software concepts.
- **Plan, don't do.** Every ticket resolves a decision. No implementation in this map — the four spec documents are the deliverable. The pull to start building is the signal we've reached the edge of the map.
- **Skills each session**: `/grilling` and `/domain-modeling` by default. `/research` for `research` tickets (AFK). `/prototype` for `prototype` tickets (HITL).
- **Subagent sizing** _(standing preference)_: run subagents on the smallest capable model at lower effort — default `research`/`task` agents to Sonnet (drop to Haiku for mechanical work); reserve the top model + higher effort for the driving session's own reasoning. For agents run via a workflow, also lower the per-agent `effort`.
- **Polyglot is incidental, not a goal.** Best tool per component. Do not force language variety for its own sake.
- **The design language is recoverable, not invented.** Harvested from the deprecated repo's CSS modules: Roboto Mono throughout (Poppins imported but barely used); monotone `#000000` / `#5F5F5F` / `#FFFFFF` plus greys `#5C5C5C` `#969696` `#9C9A9A` `#9E9C9C`; the yellow is **`#FBFF20`**, used exactly twice; signature detail is `h3:after` — a 1px rule that flexes to fill the line after each heading.
- **Cautionary fact**: the deprecated site put its Notion token in `NEXT_PUBLIC_NOTION_KEY`, which inlines it into the client bundle. custodian's auth model must not repeat this.
- **Core motivation**: the deprecated site used `getStaticProps` with no revalidation, so every content edit required a rebuild. Escaping that is the point of custodian.
- **Infrastructure principle** _(from ticket 01)_: **self-manage the compute, rent the durability.** Self-manage what fails as "it's down an hour and you learn something"; rent what fails as "the data is gone." Everything lives in **AWS eu-west-1** at ~£10/month. See [ADR-0001](../../docs/adr/0001-hosting-and-deployment-posture.md).

## Decisions so far

- **Destination is specs, not shipped code** _(charting)_ — all four components specced before building; cross-cutting decisions become ADRs.
- **Polyglot is incidental** _(charting)_ — best tool per component, no forced variety. `blank` is TypeScript by necessity, since it's a Web Components library.
- **custodian owns all three content buckets** _(charting)_ — **authored** (markdown blogs + media), **derived** (Steam currently-playing, GitHub activity — fetched and cached, never written by hand), and **profile** (about, experience, skills, resume link). Profile moving into custodian is deliberate: leaving it as repo files would partly recreate the rebuild-to-edit problem.
- **Curated projects and GitHub activity are two separate concepts** _(charting)_ — a showcase you author and order deliberately, plus a live feed custodian observes. Different lifecycles, different trust levels, rendered differently.
- **`blank` publishes to public npm with semver from the start** _(charting)_ — not because strangers will use it, but because publishing is the forcing function that stops the API silently becoming persona-shaped.
- **persona bakes profile at build time; blogs, Steam and GitHub load at runtime from custodian** _(charting)_ — custodian is therefore a hard runtime dependency for blog content, which is why health monitoring and alerting are an explicit requirement rather than a nice-to-have.
- **[CLI: name](issues/06-cli-name.md)** — the CLI is **`broom`**, the custodian's own implement. Pairs with `custodian` as a set, and stays humble about a tool that only moves content into an API. Bare npm name is squatted by a dead 2012 package, so npm distribution would need a scope; Homebrew and Go paths are clear, crates.io unverified.
- **[Hosting and deployment posture](issues/01-hosting-and-deployment-posture.md)** — all AWS, eu-west-1, ~£10/mo. custodian is a long-lived **EC2 `t4g.micro`** running nginx + systemd by hand, with **SQLite in-process** replicated to **S3**; media is S3; persona is a private S3 bucket behind **CloudFront**, leaving Netlify. **One CloudFront distribution fronts both**, so blogs cache at the edge and the API is same-origin. Credentials come from an **IAM instance profile** — nothing long-lived on disk, which is what won AWS over a cheaper Hetzner + R2 build. DNS delegates to Route 53.
- **The destination is redrawn to five components** _(surfaced by [Hosting and deployment posture](issues/01-hosting-and-deployment-posture.md))_ — **`deed`**, the Terraform component, joins the set. The name follows the rule: a single evocative noun, the authoritative declared record of the ground the playground sits on. It provisions the playground *and* projects beyond it, which gives it `blank`'s property — its interface must not become playground-shaped.
- **[Authored-content domain model](issues/03-authored-content-domain-model.md)** — the ubiquitous language for all three buckets, now in `CONTEXT.md`. `log` is the one first-class authored type (fields + `listed`/`unlisted` state where every log is link-reachable and slug freezes only while listed; **GFM core**, no footnotes, no novel syntax, blockquote doubles as margin aside). `media` is independent and generic-URL'd with a `broom` reference-check before delete. `profile` is a keyed id+`body` table (`about`/`experience`/`skills`/`resume-link`/`curated-projects`, opaque JSON, no custodian validation); `integration` mirrors that shape for derived sources. **Scope held:** the Notion-style user-defined-type/BaaS idea was ruled a future direction, not v1 — same "capable-of, don't-build" framing as `blank`/`deed`.
- **[blank: design language extraction](issues/04-blank-design-language-extraction.md)** — the design language, verified against the deprecated `globals.css` and resolved by prototype. **Roboto Mono 400 for all chrome; hierarchy from spacing plus a small size step, never weight** — whitespace does the majority over a gentle 20/16/15px scale (h1/h3/body) well below the old CSS's 32/20/14. **Colour balanced against size** so presence is uniform: the larger the element the more its ink fades (h1 `#5F5F5F`, body full ink). **Headings centered and standing alone, body text justified and block-centered on the page**; the recovered `h3:after` hairline rule is dropped (no flanking rules on centered headings). **Everything is lowercased (leading letter included) — chrome *and* headings — except running body prose**, which keeps authored casing; casing marks the one class of text meant to be read normally. **Roboto Serif for long-form prose** — the chosen companion, kept inside the Roboto superfamily so it shares the skeleton. Poppins confirmed dead, dropped. **Fearlessly monotone**: `#FBFF20` kept exact and used **only as a background highlight** — links are ink-underline, status dots ink, and in data viz the yellow is a single spark, never a fill. the `h3:after` hairline is **dropped** — with centered, standing-alone headings the flanking rules are cut; heading separation is pure whitespace (~64px above / ~24px below an h3), never a drawn rule. **Dark theme is first-class from the start** (the monotone palette makes it cheap, and it reads better than light). Validated viz primitives — **square stat tiles** and a **drawn SVG line/area chart with mono axis labels** — belong in the component inventory.
- **[blank: Web Components strategy](issues/05-blank-web-component-strategy.md)** _(research)_ — primary-source facts for the Lit-vs-vanilla and Shadow-vs-light-DOM calls; full findings in [`research/05-blank-web-components-strategy.md`](research/05-blank-web-components-strategy.md). Lit is a **~5 KB** versioned runtime giving property/attribute sync + batched render + template diffing you'd otherwise hand-write; Shadow DOM is the first-party default (Lit calls light DOM "generally not recommended"); **`adoptedStyleSheets`** (Baseline Mar 2023) kills per-instance style duplication; theming crosses the boundary only via inherited **custom properties** + opt-in `::part()`/`::slotted()`. **Pivotal SSR asymmetry:** **Declarative Shadow DOM is a platform feature, Baseline Aug 2024, works everywhere; Lit's own SSR is experimental (`@lit-labs/ssr`)** — so vanilla pre-renders library-independently while Lit's pre-rendering leans on non-stable tooling. React 19 closed the last framework-interop gap (100% Custom Elements Everywhere); Astro/Svelte/Vue already fine. **The Lit-vs-vanilla decision itself is deferred to [blank: rendering foundation](issues/21-blank-rendering-foundation.md), which now gates [persona: framework](issues/15-persona-framework.md) in place of this research.**
- **[Steam and GitHub API capabilities](issues/02-steam-and-github-api-capabilities.md)** — both APIs support a poll-and-cache model well inside their rate limits (Steam: 100,000 calls/day; GitHub: 5,000/hr authenticated, 304s free); the real constraint is freshness *shape*, not quota. Steam: a self-owned key bypasses privacy gating entirely, and `GetRecentlyPlayedGames` beats live presence for a rarely-polled site. GitHub: `events/public` polled every 1–2 min with a zero-permission PAT and ETag conditional requests, but GitHub documents 30s–6h latency on that feed — UI copy must say "recently active," not "live."
- **[custodian: storage model](issues/08-custodian-storage-model.md)** — **SQLite is the sole source of truth** (the git-hybrid fork weighed and dropped — it adds git *on top of* `07`'s embedded engine and forks `01`'s one-file durability path). `log` bodies are a column; **version history deferred** (overwrite-in-place + `created_at`/`updated_at`; a `log_revision` table is additive fog). **Media keys are a single kebab-case string** — author-given or random-kebab, uniqueness *enforced* (duplicate → error, no silent overwrite), URL extension-free (`cdn.mihirsingh.dev/<key>`) with content-type from the record; content-addressing rejected (dedup irrelevant, immutability fights image-swap). **`integration` cache shares the same SQLite store** (no Redis/in-memory — one boring durable thing). **Recovery: Litestream-style WAL shipping for per-timestamp PITR + S3 versioning on both DB and media buckets, 30-day retention** — covers self-inflicted bad writes/deletes, not just instance loss. *Open caveat: confirm the 30-day retention S3 cost against `01`'s ~£10/mo when buckets are configured.* Unblocks `09`; writes are fully synchronous.
- **[custodian: API contract](issues/09-custodian-api-contract.md)** — **REST/JSON, OpenAPI 3.1 spec-first** (Go + TS clients generated from one `.yaml`). **Two surfaces in one binary, split by audience:** a public `/v1/*` read surface (unauth, GET-only, `ETag`+`Cache-Control`+`304`, static-config CORS allowlist) and an authenticated admin `/admin/v1/*` CRUD surface (`no-store`, no CORS). **Media** uploads via **presigned S3 `PUT`** — reserve (`pending`, key uniqueness enforced) → upload → `confirm` (custodian `HEAD`s S3) → `available`; stale reservations reaped by the existing poller; `broom` needs no AWS creds. **Slug is a log's sole identity** (mutable while unlisted, frozen while listed; rename is a server move); logs are `POST`/`PATCH`/`DELETE` with `state`/`slug` as fields. Profile `PUT`-upsert opaque; integrations poller-driven + a manual `/refresh`. Errors are **RFC 9457 `problem+json`** + stable `code`. Versioned by **URL path `/v1`** (additive-only within a major). *No spec artifact built — the decision record carries draft request/response sketches; the OpenAPI `.yaml` is destination-spec work.* Unblocks `10`/`12`/`17`; hands `12` the TTL numbers and `10` the header-not-cookie auth scheme.
- **[custodian: auth model](issues/10-custodian-auth-model.md)** — **single hashed bearer token** on `Authorization: Bearer` (custodian stores only the hash; mTLS/OAuth dropped as multi-user ceremony, upgrade path kept in fog). `broom` stores it in a **`0600` config file** (XDG) with a winning **`BROOM_TOKEN` env override**; `login` verifies with one authed call, no OS keychain. **Two log states only** (`listed`/`unlisted`), every fetched log public, **no private-preview third state**. **Third-party keys + token hash are custodian-side only**, read from the process environment at startup — **10 sets the invariant, `deed` picks the store** (env/SSM/EnvironmentFile), persona never touches them. **Single-token replace-and-restart rotation**, revocation implicit, no self-credential endpoints; leak detection = admin access logging → **`11`**. **Two abuse layers:** nginx `limit_req` (per-IP, per-location, real-client-IP via CloudFront XFF) for origin hammering, and — chosen **Option B** — an **AWS WAF rate-based rule + Budgets alarm** for edge-cache **wallet-DoS** (Budgets alone can't cap the bill; an unmitigated 100M-req/~20 TB month ≈ $1,678, WAF ~$6/mo turns it into ~$66). **Budget tension → `01`** (~£15/mo, over the ~£10 target, a blessed breach). Costing in [`docs/research/aws-cloudfront-wallet-dos-pricing.md`](../../docs/research/aws-cloudfront-wallet-dos-pricing.md).
- **[custodian: observability, monitoring and alerting](issues/11-custodian-observability.md)** — **one monitoring plane (Grafana Cloud free tier), custodian instrumented agentlessly via OpenTelemetry.** No CloudWatch (metered → budget-leak), no on-box Prometheus/Grafana (dies with the box), no agent sidecar, no separate uptime prober, no blank status page in v1. Custodian embeds the **OTel Go SDK** and exports **OTLP/HTTP directly** to Grafana Cloud (metrics + traces + **logs** all OTLP; on-box `journald` only a fallback buffer) — **vendor-neutral by construction** (backend is a config URL) and the blessed way to *learn OTel*. Health is a self-assessed **`health` gauge** (`1`/`0` from SQLite + S3 + disk/mem; **third-party APIs excluded** so Steam-down ≠ custodian-down); the gauge *is* the heartbeat, so **one alert rule — `health==0` OR `no-data-for-window` — → Grafana IRM → mobile push** (confirmed free-tier). HTTP health endpoint demoted to **debug-only** `/healthz`. **Derived widgets serve last-known value + `updated_at`, no cutoff, persona decides staleness display** (feeds `12`/`16`). **Custodian-down → accept empty + CloudFront edge-cache softens brief outages**; build-time blog snapshot deferred (it'd reintroduce the build-to-edit staleness custodian exists to escape). Adds **~£0/mo** (free tier, no card attached = the leak off-switch). Status page folds into persona's page-inventory fog.
- **[Derived data: freshness and caching](issues/12-derived-data-freshness-and-caching.md)** — **one 5-min poll tick** (both sources per tick, GitHub via `If-None-Match`, interval config-overridable) on `09`'s existing scheduled poller; derived rows in the same SQLite store. Read surface stamps **`max-age=60, s-maxage=60, stale-while-revalidate=300`** (short edge TTL under the poll interval so no reader pays origin latency). **No manual value override in v1** — derived stays purely observed (`03`); a pin/suppress write is fog. **Idle is the *absence* of a change, not a rendered state:** idle/empty polls don't insert and don't bump `updated_at`, so persona sees `304`s and idle/failure are indistinguishable by design; startup poll guarantees a row, empty-array → persona hides the widget. **Custodian has zero opinion on data age** (holds `11`) — always carries the fetch timestamp, persona owns the "recently active → stale" threshold (feeds `14`/`16`). **Revises `08`: integration storage goes upsert → append-on-change timeseries** (row per distinct state) to enable future timelines; read still serves latest, a history endpoint is fog. **Data kept indefinitely; recovery window stays `08`'s 30 days.**
- **[Monorepo tooling and layout](issues/13-monorepo-tooling-and-layout.md)** — **flat, named top level** (`custodian/ broom/ blank/ persona/ deed/` — filesystem mirrors the ubiquitous language, no `apps/`/`packages/`). **`deed` lives in-repo but nothing applies it today** (CI caps at `fmt`/`validate`/`plan`; a gated CI-apply is future, not foreclosed → `18`). **Thin root `justfile`** delegating to each component's native toolchain — no Bazel/Nx (bar is a measured pain, not tidiness). **pnpm workspaces for the TS components only**; Go/HCL have no `package.json` so pnpm is blind to them — no entanglement. **Generated API client: one OpenAPI `.yaml` under custodian, `just gen` fans a vendored client into each consumer** (`broom`/persona/custodian-tests) in its own language — **no shared client package**, generated code **committed**, **CI drift-checked**. **Per-language formatters/linters** as `just` recipes + CI (Terraform state never committed); **no pre-commit hook v1**. **Clean git start** — deprecated repo archived, history not imported; **`master`→`main`** now. Unblocks `19`.
- **[blank: component inventory](issues/14-blank-component-inventory.md)** — `blank` is a **primitives + tokens** library, not a component kit; the line is the **different-project test** (belongs in `blank` iff it'd make sense in a non-CV project — anything *field-aware* is persona's), and `blank` **grows with the implementations it powers** (minimal set, add on need). **v1 ships one non-component deliverable + six components:** a **base/tokens stylesheet** (monotone palette, 20/16/15 scale, dark theme, global `<a>` ink-underline, centered/lowercased/whitespace-separated headings — so no `<blank-link>`), plus **`<blank-stack>`** (pure spacing, no heading/icon slots), **`<blank-card>`** (padded box, one slot), **`<blank-markdown>`** (client-side md renderer + monotone runtime highlighting; centralises rendering so custodian stays a raw-markdown store; **no long snippets** — long code redirects out), **`<blank-badge>`** (text + animated ink `dot` attribute; the live-status surface is an instance), **`<blank-button>`** (`primary`/`secondary`/`icon`, icon is a slot), **`<blank-stat>`** (square stat tile). **Persona, not blank:** navbar/hero/about/experience/project/skills/footer/post-list-item/out-of-prose-images and the status *line* — compositions of the six. **Fog:** SVG chart (graduates with a dashboard project), bare dot, `inline` primitive, icon set, `<blank-section>`. **Feeds `21`** (parser weight + `::slotted` styling constraint) and **`16`** (`<blank-markdown>` must be SSR-able or blogs aren't crawlable).
- **[CLI: language, UX and distribution](issues/17-cli-language-ux-and-distribution.md)** — **`broom` is Go**, sharing custodian's generated OpenAPI client (`09`/`13`). **Authoring: `broom logs new` prompts metadata → creates an `unlisted` post immediately (slug *is* the post) → `$EDITOR` on the body → `PATCH` on save; `logs edit <slug>` round-trips identically. Custodian is canonical — no local git repo of posts; empty bodies allowed.** **Media is a separate terminal gesture** — `broom media add <file> [--key k]` runs `09`'s presigned reserve→upload→confirm and **prints + clipboard-copies legible `![](…/media/<key>)`**; the author-given kebab key is the ergonomic win. **Revises `08`: media URL gains a `/media/` prefix** (`cdn.mihirsingh.dev/media/<key>`). Noun-grouped verbs (`logs`/`media`/`profile` + top-level `login`/`logout`; _`integration` group later dropped by [custodian: integration definition model](issues/24-custodian-integration-definition-model.md)_); `profile edit <key>` opens raw JSON in `$EDITOR` (`03`). **No local preview** — `unlisted`-on-persona is the true-fidelity preview, broom ships no renderer. **Distribution: build from source via a root `just install`** (`13`); published distribution (tap/GoReleaser/`go install`) is fog. **Config: one XDG file holds `url`+`token`** (extends `10`), baked default URL, `BROOM_URL`/`BROOM_TOKEN` overrides, no staging/named-env in v1.
- **[deed: state backend and apply authority](issues/18-deed-state-backend-and-apply-authority.md)** — **Terraform** (not OpenTofu — career-aligned, mirroring `07`'s Go logic; BUSL harmless at this scale). **State in S3 with native locking** (`use_lockfile`, TF 1.10+ — drops the legacy DynamoDB lock table, same "one fewer moving part" instinct as `08`/`11`); **never committed to git** (state is plaintext secrets → the `NEXT_PUBLIC_NOTION_KEY` mistake in another file, and "if it's gone it's gone" data `01` rents rather than self-manages). **State bucket bootstrapped by hand once and referenced, never Terraform-managed** (managing the bucket that holds its own state is a footgun; the one place clicking beats declaring). **Apply is laptop-only under short-lived IAM Identity Center (SSO) creds** — no static key for the one identity that can destroy everything (sharpest case of `01`'s "nothing long-lived on disk"); **CI never applies** (deed CI stays `fmt`/`validate`/`plan` per `13`; GitHub OIDC parked as fog for a future gated CI-apply). **Blast radius: multiple state files split by logical component** (exact boundaries left to implementation), with **`prevent_destroy` on the data buckets** as the layout-independent safety invariant. **Drift accepted as personal responsibility** — no scheduled plan (would reintroduce the standing-creds surface just eliminated), surfaces at next apply. Unblocks `20`.
- **[deed: provisioning boundary](issues/19-deed-provisioning-boundary.md)** — **`deed` provisions the durable shell; a deploy owns the app layer** — a **mutable long-lived box, immutable app layer** (containers cattle, box + SQLite volume pets). Everything is **Docker via `docker compose` on one EC2** — **ECS rejected** (Fargate breaks SQLite-on-local-disk + costs ~3×; ECS-on-EC2 is ceremony for one box). **`deed` provisions:** EC2 + EBS + `user_data` (Docker/compose/AWS-CLI, stops at "engine running"), the SQLite Docker volume, **ECR repo + lifecycle policy + instance-profile pull grant** (ECR beat GHCR on cost *and* zero-static-cred pull — [`docs/research/ecr-vs-ghcr-pricing.md`](../../docs/research/ecr-vs-ghcr-pricing.md)), the persona S3 bucket + CloudFront distribution, and the instance profile. **A deploy owns** `compose.yml`+`nginx.conf`, **builds locally → pushes to ECR** (SSO creds, **builds stay local for now, no CI publish**), triggers custodian via **`just deploy-custodian` → SSM Run Command** (no SSH key), and publishes persona via **laptop `s3 sync` + invalidation** under SSO. **`systemd` dissolves into Docker restart policies; Litestream becomes a sidecar.** **Secret model** _(secret split later collapsed by [custodian: integration definition model](issues/24-custodian-integration-definition-model.md) — see below)_: originally two classes — integration keys in custodian's SQLite, broom-written; **bootstrap secrets** (admin-token hash `10`, **Grafana OTLP token `11`**) **env-at-startup via SSM→tmpfs-env**, `deed` owning the param + read grant but never the runtime injection (custodian reads only `os.Getenv`). **No long-lived AWS keys anywhere** (instance profile / SSO / future OIDC). *Revises `11`* (names the OTLP cred), *`01`* (nginx+systemd-by-hand → Docker+compose). The self-hosted-secrets-manager rejection stands. Unblocks nothing new; **CloudFront↔origin security** and **CI build-and-publish/OIDC** parked as fog.
- **[deed: multi-project layout](issues/20-deed-multi-project-layout.md)** — the minimum structure that keeps `deed` from going playground-shaped **without building any multi-project machinery today**. **Single in-repo config** (not the `blank` published-module pattern — that's fog until a real second repo needs it). **Flat HCL now, no modules** — extract on the first real second consumer (rule of three, against two concrete examples not one imagined interface); flat forecloses nothing, so "capable of other projects" holds. **Versioning moot** (nothing published to pin). **The one deliberate "more moving parts" call: AWS Organizations now, playground in its own member account** — taken purely on retrofit-pain (cross-account moves of S3/CloudFront/ACM/Route 53 are real migrations; enabling the Org is near-free today), so **project-two is a new account, not a migration**. **State bucket per account** completes the isolation (`18`'s hand-bootstrap gesture repeated per account; per-component split unchanged *inside* the playground account). *Revises `18`/`19`* — their single-account SSO framing is now the playground's own member account. **Fog:** published-module distribution + its versioning.
- **[blank: accessibility](issues/22-blank-accessibility.md)** — **a11y is a cheap floor for v1, not a commitment** (full accessibility explicitly deprioritised for this destination). `blank` bakes in only the near-free-*and*-expensive-to-retrofit shapes: **`<blank-button>` is a real native `<button>`** (real links are real `<a>`), the base stylesheet **never suppresses native focus** without a replacement, **`prefers-reduced-motion`** stops `<blank-badge>`'s animated dot, and **`<blank-button icon>` accepts+passes through an `aria-label`** (mechanism only). **Split:** `blank` owns native semantics / focus-not-broken / reduced-motion / aria-label passthrough; persona owns heading order, alt text, and the actual aria-label *values*. **Fog:** WCAG 2.2 AA audit + contrast tests, dark-theme + `#FBFF20`-text-bg contrast verification, monotone focus-ring *design*, `<blank-markdown>` AT semantics, and *enforcing* icon accessible names — all graduate only under a future dedicated a11y effort.
- **[blank: rendering foundation](issues/21-blank-rendering-foundation.md)** — the two coupled foundational calls, settled by grilling `05`'s facts + one research pass. **SSR posture (B): blog *prose* server-rendered as plain semantic HTML in the payload; decorative `blank` chrome hydrates client-side** (time-to-paint a watched metric). **Authoring: Lit** (~5 KB **`peerDependency`** to dedupe; `@customElement` throughout) — a deliberate override of the paint-minimising vanilla case, taken for idiomatic ergonomics + CEM tooling; the SSR penalty `05` pinned on Lit is dissolved because nothing renders shadow prose on the server, so **`@lit-labs/ssr` is never a dependency**. **Encapsulation: mixed** — Shadow DOM for the five chrome components (scoping + un-leakable internals, decisive for a *published* lib; `adoptedStyleSheets` shares one sheet), **light DOM for `<blank-markdown>`'s prose** (the one exception, so prose is crawlable + fast-painting and styled by the global base sheet). Verified: WebC, Enhance, *and lit.dev itself* ship prose-in-light-DOM, chrome-in-shadow; even Lit's team avoids `@lit-labs/ssr` for prose. All-light rejected (surrenders class-leak protection + makes Lit non-idiomatic); uniform-shadow+DSD rejected (that's exactly the `@lit-labs/ssr`-for-prose bet the ecosystem avoids). **Theming: CSS custom properties only, no `::part()` v1** — tokens-as-custom-properties is *forced* (only channel that both crosses the shadow boundary and styles light-DOM prose); `::slotted()` internal-only. **Packaging: ESM-only**, per-component subpath `exports` + barrel; **v1 ships the idiomatic auto-registering entry only** (`@customElement` side-effect, `sideEffects`-listed); bare-class/per-consumer-`register()` dual entry deferred to fog (non-breaking additive). **Custom Elements Manifest: yes** — analyzer-generated, committed, CI-drift-checked (mirrors `13`). **Surfaced `23`** (blog delivery model), which now blocks `15`.
- **[persona: blog delivery model](issues/23-persona-blog-delivery-model.md)** — **blogs are build-time SSG in a hybrid delivery model**; persona keeps **no long-lived render tier** (static objects on S3/CloudFront per `01`/`19`). SEO is **general, not Google-only** → prose *must* sit in the initial HTML payload (non-Google crawlers + social unfurlers don't run JS), which **kills the charting decision's "blogs load at runtime via client fetch."** With prose-in-payload the invariant, the two tier-free contenders were prerender-to-static (SSG) and serverless/edge-SSR-on-cache-miss; **SSG won on low blog cadence + "just files" over default freshness** (custodian-SSR-at-origin rejected — presentation-in-custodian + blog-down-if-custodian-down; long-lived persona server rejected). **Trigger is manual** — a `just`/deploy rebuild *you* run to batch posts live; **no custodian→persona webhook, no timer** (broom/custodian stay ignorant of persona). ## Out of scope

Ruled beyond this destination. Never graduates — returns only as a fresh effort if the destination is redrawn.

- **Building any of it.** The destination is specs. Implementation is a separate effort per component.
- **Incrementally migrating the deprecated site.** persona is a port to a new environment, not a refactor in place. The old repo is a source of design tokens and a content model, nothing more.
- **Adopting `blank` in other personal projects.** `blank` must be *publishable* and its API must not be persona-shaped, but actually wiring it into other projects is their own work.
- **The deprecated site's Notion workspace** beyond reading what content types it held. No two-way sync, no keeping Notion in the loop.
- **Actually provisioning non-playground projects with `deed`.** `deed` must be *capable* of it — its interface must not become playground-shaped — but standing up other projects' infrastructure is their own work. Mirrors the `blank` ruling above.
