Animate it — the render loop & the glide

The win: make the cube move on its own with requestAnimationFrame, and make that motion glide instead of snap — the two techniques (easing + lerp-follow) your prototype uses for its buttery feel.

1. Animation = redraw with a changing number

There's no magic. Animation is just: pick a number, change it a little, redraw, repeat. You already have draw() from Lesson 4. Wrap it in a loop that nudges the angle each frame:

let angle = 0;
function loop(){
  angle += 1;            // change the number
  draw(angle);           // redraw the scene
  requestAnimationFrame(loop);   // ask the browser for the next frame
}
requestAnimationFrame(loop);

requestAnimationFrame(loop) asks the browser to call loop once, right before the next repaint (~60×/sec). Call it again inside the loop and you have a render loop. This is the prototype's loop().

WATCH OUT — angle += 1 ties speed to frame rate: a 144Hz screen spins ~2.4× faster than 60Hz. The fix is time-based motion — multiply by elapsed time (angle += speed · dt). The prototype dodges this because scroll drives it, not the clock — but remember the rule for clock-driven motion.

2. Easing — motion shouldn't be robotic

Linear motion (constant speed) feels mechanical. Easing reshapes a 0→1 progress value so it starts slow, speeds up, ends slow. smoothstep is the classic:

function smoothstep(t){ return t*t*(3 - 2*t); }   // ease-in-out on [0,1]

Feed your raw progress through it before using it. Same start and end, nicer middle.

3. The lerp "smooth follow" — the glide

This is the trick that makes your prototype feel premium. Instead of jumping straight to a target value, each frame you move a fraction of the remaining distance:

cur += (target - cur) * 0.12;   // 12% of the way there, every frame

Because the step shrinks as you approach, motion decelerates naturally — a critically-damped, spring-like glide. Set a new target and it eases over; the raw input can jump, but cur always slides. Your prototype does exactly this with the scroll value so the scene doesn't snap frame-to-frame.

4. Play with the glide

Drag target and let go — the cube eases to it, it doesn't jump. The follow slider is that 0.12: higher = snappier, lower = floatier. Watch cur chase target.

Try k = 1.0: the cube snaps instantly (no glide). Try k = 0.04: it drifts over lazily. 0.12 is the prototype's sweet spot.

5. Full circle — you can now read the prototype

Scroll-driving is just this with a different number source: instead of a slider setting target, the scroll position (normalised to 0→1, passed through smoothstep) sets it, and the same lerp-follow smooths it. That's the entire animation system in CONCEPTS §4.
